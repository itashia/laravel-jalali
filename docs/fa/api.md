# مرجع تاریخ و زمان

## مقادیر و ساعت

`JalaliDateTime` تغییرناپذیر است. متدهای سازنده: `create`, `parse`, `parseFormat`,
`fromDateTime`, `fromCarbon`, `fromTimestamp`. ورودی‌های `DateTimeInterface` و
Carbon، میکروثانیه و منطقهٔ زمانی را حفظ می‌کنند. `toDateTime` و `toCarbon`
مقادیر تغییرناپذیر برمی‌گردانند. فکتوری کانتینر (`Jalali\Jalali\Jalali`) و
Facade به‌نام `Jalali`، متدهای `now`, `today`, `yesterday`, `tomorrow`,
`create`, `parse`, `fromDateTime`, `fromCarbon`, `toGregorian` را در اختیار می‌گذارند.

```php
use Jalali\Jalali\JalaliDateTime;

JalaliDateTime::parse('1405/08/19');
JalaliDateTime::fromDateTime(new DateTimeImmutable('2026-11-10 09:00:00'));
JalaliDateTime::fromCarbon(\Carbon\Carbon::now());
```

فکتوری از تنظیمات `laravel-jalali.timezone` استفاده می‌کند (پیش‌فرض UTC).
ارسال صریح منطقهٔ زمانی این مقدار را بازنویسی می‌کند. تنظیمات هنگام ساخت
singleton خوانده می‌شوند؛ برای کارگرهای طولانی‌مدت که نیاز به تنظیمات
درخواست‌به‌درخواست دارند، آرگومان صریح بدهید. برای کنترل زمان جاری در تست‌ها
یک Closure به فکتوری تزریق کنید (`new Jalali($clock)`)؛ ساعت تستی سراسری
وجود ندارد.

موتور تقویم `PersianCalendar` از سال‌های شمسی ۱ تا ۳۱۷۷ پشتیبانی می‌کند و
متدهای `toGregorian`, `fromGregorian`, `isLeapYear`, `daysInMonth` را فراهم
می‌کند. این موتور از الگوریتم سال کبیسهٔ مستندشده در
[research](../research.md) پیروی می‌کند.

## تابع سراسری

```php
jalali()->format('Y/m/d H:i:s');                    // ساعت پیکربندی‌شده
jalali('1405/08/19');                                // رشتهٔ دقیق جلالی
jalali(new DateTimeImmutable());                     // لحظهٔ میلادی
jalali(\Carbon\Carbon::now(), 'Asia/Tehran');         // Carbon با منطقهٔ زمانی صریح
```

`jalali(string|DateTimeInterface|null $value = null, ?string $timezone = null): JalaliDateTime`
رشته‌ها را تاریخ جلالی با قالب `YYYY/MM/DD` تفسیر می‌کند؛ مقادیر
`DateTimeInterface` (از جمله Carbon) لحظه‌های میلادی هستند. مقدار null با
استفاده از فکتوری کانتینر به زمان جاری تبدیل می‌شود. این تابع از طریق
`autoload.files` کامپوزر بار می‌شود و با `function_exists` محافظت شده است،
بنابراین هرگز یک تابع `jalali()` از پیش موجود را بازنویسی نمی‌کند.

## تجزیه و تبدیل

`parse` قالب دقیق `YYYY/MM/DD` می‌خواهد. `parseFormat(format, input, timezone)`
از نشانه‌های `Y m d H i s u` پشتیبانی می‌کند: به‌ترتیب سال چهاررقمی، ماه/روز/
ساعت/دقیقهٔ دورقمی، ثانیه و میکروثانیهٔ شش‌رقمی. `Y`، `m` و `d` باید دقیقاً
یک‌بار ظاهر شوند؛ اجزای زمانی پیش‌فرض صفر دارند. نویسه‌های فرار و علائم
نگارشی باید دقیقاً مطابقت داشته باشند. نشانه‌های پشتیبانی‌نشده، تکراری،
ورودی نادرست و تاریخ نامعتبر خطای `InvalidDate` ایجاد می‌کنند. هر سه دستگاه
عددی (انگلیسی، فارسی، عربی-هندی) حتی به‌صورت مخلوط پذیرفته می‌شوند. فاصلهٔ
خالی حذف نمی‌شود.

```php
JalaliDateTime::parseFormat('Y-m-d H:i', '1405-08-19 09:30');
JalaliDateTime::parse('۱۴۰۵/۰۸/۱۹'); // ارقام فارسی
```

## قالب‌بندی

`format()` از نشانه‌های `Y m n d j F l z t L`، نشانه‌های زمان `H G h g i s u a A`،
نشانه‌های منطقهٔ زمانی `P O e` و برچسب زمانی `U` پشتیبانی می‌کند. `F` و `l` نام
ماه و روز هفته به فارسی هستند. `z` روز سال صفرپایه، `t` تعداد روزهای ماه و `L`
پرچم کبیسه است. علائم نگارشی عیناً چاپ می‌شوند و بک‌اسلش نویسهٔ بعدی را فرار
می‌دهد. حروف انگلیسی پشتیبانی‌نشده خطای `InvalidDate` ایجاد می‌کنند. برای
ارقام فارسی آرگومان دوم را `true` بدهید. نشانه‌های قبل‌ازظهر/بعدازظهر همچنان
انگلیسی باقی می‌مانند.

```php
jalali('1405/08/19')->format('l j F Y', true); // روز هفته، روز، ماه و سال فارسی
jalali('1405/08/19')->diffForHumans(jalali('1405/08/20'));
```

`diffForHumans(reference)` متن نسبی فارسی تولید می‌کند و ثانیه‌های سپری‌شده را
به روز/ساعت/دقیقه/ثانیه کوتاه می‌کند؛ هر روز به معنای ۸۶۴۰۰ ثانیه است، نه مرز
تقویمی روز. این متد برای پرهیز از وابستگی پنهان به ساعت سراسری، یک تاریخ
مرجع صریح می‌خواهد.

## محاسبات و مقایسه

`addDays/Weeks/Months/Years/Hours/Minutes/Seconds` و معادل‌های `sub*` مقدار
جدید برمی‌گردانند. آرگومان منفی جهت را معکوس می‌کند. محاسبات روز/هفته از
تقویم محلی و محاسبات ساعت/دقیقه/ثانیه از زمان سپری‌شدهٔ UTC پیروی می‌کنند.
تغییر ماه/سال به آخرین روز معتبر مقصد محدود می‌شود. محاسبات خارج از بازهٔ
معتبر رد می‌شوند؛ معکوس‌کردن یک تغییر ماهِ محدودشده لزوماً روز اصلی را
بازنمی‌گرداند.

```php
jalali('1405/08/19')->addDays(10)->subMonths(2);
jalali('1405/01/31')->addMonths(1); // به 1405/02/31 محدود می‌شود، یعنی آخرین روز معتبر
```

`startOf*` / `endOf*` از Day، Week، Month، Quarter و Year پشتیبانی می‌کنند.
هفته از شنبه شروع می‌شود. مرزهای پایانی `23:59:59.999999` هستند. نیمه‌شب محلی
از تفکیک منطقهٔ زمانی PHP استفاده می‌کند؛ نیمه‌شب ناموجود ممکن است به اولین
زمان معتبر تفکیک شود. `create` صریح، ساعت دیواری ناموجود را رد می‌کند. ساعت
دیواری تکرارشده از انتخاب آفست PHP پیروی می‌کند.

`compare`, `equals`, `isBefore`, `isAfter` لحظه‌ها را مقایسه می‌کنند. `diff`
یک `DateInterval` بومی برمی‌گرداند؛ `diffInSeconds` یک اختلاف علامت‌دار
اعشاری (دیگری منهای این) با محدودیت دقت اعشاری برای تاریخ‌های دور
برمی‌گرداند. `isPast`, `isFuture`, `isToday` یک تاریخ مرجع صریح می‌خواهند.
`dayOfWeek` شنبه را صفر در نظر می‌گیرد؛ `dayOfYear` صفرپایه است. `daysInMonth`
و `isLeapYear` از موتور تقویم استفاده می‌کنند.

## یکپارچگی با Carbon

```php
$carbon = jalali('1405/08/19')->toCarbon();          // CarbonImmutable، لحظهٔ میلادی
$jalali = JalaliDateTime::fromCarbon($carbon);
```

`toCarbon()` یک `CarbonImmutable` برمی‌گرداند. `fromCarbon(CarbonInterface $date)`
و `fromDateTime(DateTimeInterface $date)` هر دو ورودی را لحظهٔ میلادی در نظر
می‌گیرند و منطقهٔ زمانی و میکروثانیهٔ آن را حفظ می‌کنند.

## بومی‌سازی

دستگاه عددی (انگلیسی، فارسی، عربی-هندی) در هر فراخوانی `format()` از طریق
آرگومان دوم بولی انتخاب می‌شود؛ تجزیه هر سه دستگاه را حتی به‌صورت مخلوط، بدون
نیاز به پیکربندی می‌پذیرد. نام ماه و روز هفتهٔ فارسی (`F`, `l`) و متن نسبی
`diffForHumans` از طریق `src/Localization/Persian.php` و
`lang/{en,fa}/messages.php` فراهم می‌شوند؛ قبل‌ازظهر/بعدازظهر همچنان انگلیسی
باقی می‌ماند. هیچ کلید زبان سراسری‌ای وجود ندارد — بومی‌سازی به‌صورت صریح در
هر فراخوانی یا هر کلید ترجمه انجام می‌شود.

## کاست‌های Eloquent

```php
protected function casts(): array
{
    return [
        'occurred_at' => \Jalali\Jalali\Laravel\Casts\JalaliDateTimeCast::class.':UTC',
        'birthday' => \Jalali\Jalali\Laravel\Casts\JalaliDateCast::class,
    ];
}
```

ذخیرهٔ تاریخ‌وزمان از قالب تاریخ مدل و منطقهٔ زمانی صریح استفاده می‌کند. برای
دقت میکروثانیه، `$dateFormat = 'Y-m-d H:i:s.u'` را تنظیم کنید و از ستونی در
پایگاه‌داده استفاده کنید که ثانیهٔ اعشاری را پشتیبانی می‌کند؛ در غیر این‌صورت
قالب ذخیرهٔ پیکربندی‌شده عمداً دقت اعشاری را از دست می‌دهد. سریال‌سازی JSON به
صورت میلادی و ISO 8601 با UTC است. کاست فقط‌تاریخ، `YYYY-MM-DD` را با اجزای
تاریخ محلی ارائه‌شده و بدون تغییر منطقهٔ زمانی ذخیره می‌کند؛ خوانش یک مقدار
حامل در نیمه‌شب UTC برمی‌گرداند. مقدار JSON آن `YYYY-MM-DD` میلادی است. هیچ
رفتار سراسری پایگاه‌داده یا سریال‌سازی تغییر نمی‌کند. هر دو کاست هنگام نوشتن
`JalaliDateTime`، `DateTimeInterface` یا `null` را می‌پذیرند. رشته‌ها را
به‌صورت صریح تجزیه کنید. داده‌های ذخیره‌شدهٔ نامعتبر و انتساب رشته‌ای مبهم
خطای `InvalidDate` ایجاد می‌کنند.

## اعتبارسنجی

```php
use Jalali\Jalali\Laravel\Rules\JalaliDate;
use Jalali\Jalali\JalaliDateTime;

$rules = ['birthday' => ['required', new JalaliDate(
    timezone: 'UTC',
    minimum: JalaliDateTime::parse('1300/01/01'),
    maximum: JalaliDateTime::parse('1405/12/29'),
)]];
```

بازه‌ها لحظه‌ها را به‌صورت شامل مقایسه می‌کنند. برای اعتبارسنجی فقط‌تاریخ از
بازه‌های نیمه‌شب در یک منطقهٔ زمانی یکسان استفاده کنید. با required/nullable
لاراول ترکیب کنید؛ این قاعده ضمنی نیست. پیام‌های خطا به فارسی و انگلیسی موجود
هستند. منطقهٔ زمانی نامعتبر یا بازهٔ معکوس در سازنده، فوراً به‌عنوان خطای
پیکربندی ایجاد می‌شود.

## پیکربندی

کلید تنظیمات `laravel-jalali.timezone` (پیش‌فرض `UTC`) منطقهٔ زمانی پیش‌فرض
فکتوری را کنترل می‌کند که هنگام ساخت اولیهٔ singleton خوانده می‌شود. برای
بازنویسی آن در `config/laravel-jalali.php`، با دستور
`php artisan vendor:publish --tag=laravel-jalali` منتشرش کنید. این تنظیمات با
`php artisan config:cache` سازگار است. برای جزئیات به
[یکپارچگی با لاراول](laravel.md) مراجعه کنید.

مقادیر نامعتبر، سال‌های پشتیبانی‌نشده، قالب‌های نادرست و سرریز، خطای
`Jalali\Jalali\Exceptions\InvalidDate` ایجاد می‌کنند.
